# Dense 基线验证记录

日期：2026-10-21。

## 结论

当前保留的 LONGER、RankMixer、TokenMixer、LONGER_RankMixer 已通过小规模训练与评估验证，可以作为后续实验的代码基线。验证包含训练入口、数据拼接、六任务损失与指标、优化器更新、最佳权重保存和重新加载。

这不是全量实验结果，也不是论文复现效果报告。本版没有接入 Sparse-MoE。

## 本次修正

| 位置 | 修正原因与行为 |
| --- | --- |
| `run_expid.py` | 默认 GPU 改为单卡 0；BF16 使用明确的开启/关闭参数，未指定时遵循 YAML；初始化分布式状态后再进入清理逻辑；测试后保留最佳权重。 |
| `unirank/utils.py` | YAML 显式按 UTF-8 读取，使中文配置在 Windows 上也可直接使用。 |
| `feature_processor.py` / `build_dataset.py` | 已编码 Parquet 直接生成 feature map，跳过千万级 ID 的重复 Python 词表。 |
| `rank_dataloader.py` | 验证和测试保留每个 block 的尾部样本。 |
| `rank_model.py` | 最后不足一个梯度累积窗口时，按实际窗口 batch 数缩放损失，并在验证和保存 checkpoint 前完成参数更新；直接保存权重时创建输出目录。 |
| `model_config.yaml` | 默认关闭可选的 `torch.compile`，减少首次运行对编译环境的依赖。 |
| `.gitignore` | 忽略 `.tar` 数据压缩包；数据、虚拟环境、权重和临时输出不进入发布。 |

同时保存本地已完成的模型简化改动，包括 LONGER 的历史 padding/因果处理与组合模型。没有恢复已撤销的 MoE 功能。

```bash
python -m unittest discover -s tests -v
```

本次结果：**8 项测试全部通过**。CUDA 测试在无 GPU 的环境中会跳过，其余测试只依赖临时构造的小数据集。

- 五个实际 YAML 实验配置缩小尺寸后均完成模型构建和反向传播，包括 NoMixer 消融。

- 四种模型完成 CPU 训练、六任务 AUC/logloss 评估；保存与加载后的预测逐值一致。
- 不足完整梯度累积窗口的最后一次更新包含在保存的最佳权重中。
- 四种模型完成 CUDA BF16 训练，并开启激活重算。
- 分块加载覆盖两个局部索引空间，包含双 worker 数据读取。
- 空历史、有效曝光、候选 action 为零、历史前缀截取、padding 不变性与历史 query 的因果约束通过检查。

## 现有真实数据检查

| split | 成对 block 数 | 样本行数 |
| --- | ---: | ---: |
| train | 32 | 256,110,233 |
| valid | 8 | 34,334,869 |
| test | 8 | 33,019,342 |

检查了全部 48 组 `data/user_info/item_info` 的文件编号配对和字段，数据行数与 `meta_data.json` 一致，配置中的词表大小与 metadata 一致。该检查读取 Parquet schema/metadata，不是逐行遍历整个数据集。

另外从真实训练集取了 32 行、对应 33 个 item 条目，保留真实的用户特征、标签、历史截取与局部索引连接。为适配开发机，仅对该切片的全局 item ID 压缩编号、缩小 embedding 和网络尺寸；四种模型均完成一次 CUDA BF16 优化器更新，损失有限。切片与合成测试数据均未上传。

## 环境和未验证部分

实测环境为 Python 3.11.16、PyTorch 2.8.0+cu126、Windows、NVIDIA RTX 4070 12GB。

尚未验证 A800 80GB 上的全词表/完整模型训练、全量预处理重跑、多卡 DDP、`torch.compile`、论文效果、训练吞吐和全量显存峰值。源文件中的旧 `SparseMoELayer` 草稿没有接入模型，不能视作已实现的功能。

现有训练集约 2.56 亿行，单块约八百万行。当前加载器按整块读取，因此正式运行时除 GPU 显存外，还需根据 CPU 内存调整 `num_workers` 和 `block_cache_size`。现有 `.model` 仅保存模型权重，不包含优化器状态及断点续训信息。
